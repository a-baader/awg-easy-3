## Что такое VPN Easy Dual

Форк [AWG-Easy 3](https://github.com/alexsemenovru/awg-easy-3) с двумя
самостоятельными сервисами: AmneziaWG и стандартным WireGuard. У каждого своя
панель, ключи и клиенты; общая команда `vpnctl` управляет установкой и сервисами.

## Кратко о возможностях

- Создание и выдача VPN-профилей через браузер; сама панель доступна только внутри VPN.
- Внутренняя сеть для Home-клиентов или только интернет для Guest-клиентов.
- Раздельное управление IPv4/IPv6, диагностика соединений, установка и обновление понятными командами.

## Установка и первый вход

Для новой установки требуется Linux VPS с архитектурой `amd64`/`x86_64`, доступом от root,
установленным Git и устройством `/dev/net/tun`. WSL, macOS и BSD не поддерживаются.
При необходимости установщик подготовит Docker Engine, Docker Compose v2,
iproute2, nftables и Python 3 через поддерживаемый менеджер пакетов.

```bash
git clone https://github.com/a-baader/awg-easy-3.git
cd awg-easy-3
sudo ./vpnctl install --host PUBLIC_IP_OR_DOMAIN --lang ru
```

Замените `PUBLIC_IP_OR_DOMAIN` публичным IP-адресом или доменом вашего VPS.
Установщик скачает готовые AWG/WG-образы текущего выпуска и проверит manifest;
собирать образы на сервере не требуется. Совместимый вход
`sudo ./install.sh --host PUBLIC_IP_OR_DOMAIN --lang ru` выполняет ту же установку.

Разрешите входящий UDP в firewall VPS и в облачном firewall провайдера:
AWG использует случайный свободный порт `20000–60000`, кроме `51820`,
WG — `51824` по умолчанию. Точные порты будут в выводе установщика.
Публичный TCP-доступ к панелям открывать не нужно.

Установщик создаст для каждого VPN отдельного клиента `admin` группы Home,
ключи и пароль панели. Оба пароля показываются один раз. Для первого входа:

1. **AWG:** импортируйте показанную ссылку `vpn://` в AmneziaVPN либо файл
   `/etc/vpn-easy-dual/bootstrap/awg.conf` в совместимый клиент AmneziaWG.
   Подключитесь и откройте `http://10.8.0.1:51821`.
2. **WireGuard:** скопируйте `/etc/vpn-easy-dual/bootstrap/wg.conf` на устройство
   и импортируйте в стандартное приложение WireGuard. Подключитесь и откройте
   `http://10.9.0.1:51825`.

Используйте пароль именно той панели, к которой подключаетесь. При изменённых
портах или адресах используйте ссылки из вывода установщика. Каждая панель
доступна только через Home-подключение своего VPN; Guest и соседний VPN
к ней доступа не получают.

Если первая ссылка или профиль потерялись, выгрузите того же клиента заново:

```bash
sudo vpnctl client export --component awg --name admin --format vpn-url
sudo vpnctl client export --component wg --name admin --format conf --output /root/wg-admin.conf
```

Существующий файл экспорта не перезаписывается: выберите новое имя, если он
уже есть. Для AWG также доступен экспорт `--format conf`. Если потерян пароль,
используйте `sudo vpnctl reset-password --component awg` или
`sudo vpnctl reset-password --component wg`: новый пароль будет показан один раз.

### Панель как приложение

Подключите Home-профиль VPN, откройте панель и выберите в меню браузера **«Установить приложение»**, **«Добавить на главный экран»** или **«Создать ярлык»** — название зависит от браузера. В панели есть web-app manifest и значки для отдельного окна там, где оно поддерживается. Это не устанавливает и не запускает VPN: Home-подключение и вход в панель всё равно нужны. IPv4- и IPv6-адреса считаются разными источниками и могут создавать отдельные приложения и сеансы.

Автоматическое предложение установки PWA обычно требует **HTTPS**; стандартный внутренний HTTP-адрес этому требованию не соответствует. Некоторые браузеры позволяют добавить и его как приложение сайта или ярлык; доступность и вид зависят от браузера и ОС. Service worker, офлайн-кэш профилей и публичный порт не добавляются. См. [требования браузеров к установке](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

## Обновление и управление

После установки команда `sudo vpnctl` доступна из любого каталога и открывает
меню управления обоими сервисами. Исходники остаются нужны установленной
команде; не перемещайте каталог проекта.

```bash
sudo vpnctl help
sudo vpnctl status all
sudo vpnctl diagnose all
sudo vpnctl client list --component all
sudo vpnctl auto-update status
```

Для сохранения клиентов используйте `update`, с исходниками целевого тега и
manifest соответствующего выпуска:

```bash
sudo vpnctl update all --manifest /root/release-manifest.json --yes
```

Обновление сохраняет клиентов, ключи и пароли и предварительно создаёт snapshot.
Во время замены контейнеров возможен кратковременный разрыв VPN. Порядок
обновления с RC1 описан в [описании RC2](docs/releases/v0.2.0-rc.2.md).

В systemd/OpenRC по умолчанию включается однократная проверка stable-релиза
через пять минут после загрузки ОС; systemd добавляет задержку до двух минут.
Предварительные выпуски RC не устанавливаются этой проверкой. Управление:
`sudo vpnctl auto-update status|enable|disable|run`.

Повторный `sudo vpnctl install` для полной установки предлагает сохранить её
(по умолчанию), удалить или чисто переустановить. `uninstall` и `reinstall`
требуют подтверждения; без терминала необходимо явно указать `--yes`.
Они удаляют рабочие клиенты, ключи, пароль и настройки выбранных сервисов,
но сохраняют внутренние backup. Docker, чужие контейнеры, firewall и текущие
значения forwarding сохраняются. После удаления последнего сервиса удаляется
и установленный `vpnctl`; исходники остаются для новой установки и restore.

Параметры портов, миграция, backup и восстановление:
[установка](docs/INSTALL_DUAL.ru.md), [CLI](docs/CLI.ru.md),
[backup/restore](docs/BACKUP_RESTORE.ru.md).

## Технические возможности

> Следующие справочные разделы сохранены из оригинального AWG-Easy 3 0.1.6.
> Ограничения оригинала, например отсутствие WireGuard и backup/restore,
> не относятся к VPN Easy Dual. Актуальное устройство Dual описано в
> [DUAL_ARCHITECTURE.md](docs/DUAL_ARCHITECTURE.md).

- AWG 3.1 `HeaderProtectionKey`, `AdvancedSecurity`, новые timing/padding-поля, `RandomTrailers` и `DisableCookies`.
- Основной импорт в AmneziaVPN через локально созданную ссылку `vpn://`; `.conf` доступен дополнительно.
- Home/Guest для каждого клиента. Home видит панель и других Home peers, Guest получает только интернет.
- Независимые разрешения IPv4/IPv6 в «Настройках доступа», без переимпорта профиля.
- Состояние недавнего handshake, средняя за интервал скорость приёма/передачи, handshake и endpoint без истории трафика.
- Компактные full-tunnel профили для IPv4 и, когда VPS поддерживает его, IPv6.
- AdGuard DNS по умолчанию: `94.140.14.14`, `94.140.15.15`, а при IPv6 также `2a10:50c0::ad1:ff`, `2a10:50c0::ad2:ff`.
- Автоматический IPv6 при наличии глобального адреса и default route на VPS: отдельная ULA `/64` и NAT66 только для неё.
- Home-only mDNS и UPnP/SSDP Discovery. Управление портами через UPnP IGD, NAT-PMP и PCP, а также любой автоматический проброс портов намеренно не поддерживаются. Видимость сервисов зависит от поддержки multicast через VPN-интерфейс конкретным клиентским приложением.
- Панель слушает только внутренние адреса AWG-сети: `10.8.0.1:51821` и собственный IPv6, когда он доступен. Публичного TCP mapping нет.
- Один пароль без ролей. Смена пароля отзывает все сессии; локальный reset не требует переустановки.
- nftables в отдельной таблице `awg_easy_3`; при необходимости добавляются
  только помеченные правила для `awg0` в штатную цепочку Docker `DOCKER-USER`,
  чужие правила не очищаются.
- Нет миграции из 2.x, backup/restore и legacy WireGuard backend. Обновление с 0.1.2 сохраняет существующих клиентов.

### Настройки доступа клиента

В карточке раскройте **«Настройки доступа»** и разрешайте IPv4 и IPv6 независимо. Обе опции выключены — клиент отключён; текущий режим виден и при закрытом разделе. Home/Guest остаётся отдельной настройкой. Ограничения действуют в обоих направлениях внутри VPN, включая уже установленные соединения; ключи, профиль, адреса, DNS и маршруты не меняются. Панель защищает текущий путь администрирования и последнего разрешённого Home-клиента. Внутренние ссылки панели по IPv4/IPv6 находятся в разделе «Разрешения трафика VPN».

**В IPv6-only может перестать работать DNS:** AmneziaVPN может применять только свои IPv4-поля DNS, даже если профиль содержит IPv6 DNS. При этом прямое IPv6-соединение может работать; включение IPv4 возвращает доступ к IPv4 DNS. Исключений для DNS, NAT64, WARP и перехода на direct нет. Трафиком, исключённым из VPN клиентской раздельной маршрутизацией, панель не управляет; при базовых тестах отключайте такие фильтры. Discovery relay использует IPv4 и не включает клиентов с запрещённым IPv4.

### GeoIP-фильтрация

В «Настройках доступа» каждого клиента можно выключить фильтр, запретить выбранные страны или разрешить только их. Введите названия стран на языке панели либо двухбуквенные коды через запятую и сохраните настройку. Профиль VPN переимпортировать не нужно.

Фильтр использует IP-диапазоны, а не домены: nftables проверяет IPv4 и IPv6 в обоих направлениях VPN ↔ интернет, включая установленные соединения. Home-доступ к панели и другим Home-клиентам не меняется. Исключённые из VPN приложения не фильтруются; автоматического перехода на direct нет. Страна IP не гарантирует страну сервиса, точность или невозможность обнаружения VPN. DNS-запросы к внешнему резолверу тоже могут попасть под ограничение.

База [DB-IP Country Lite](https://db-ip.com/db/download/ip-to-country-lite) загружается и обновляется автоматически. При сбое обновления сохраняется предыдущая база; без пригодной базы активный фильтр закрывает доступ в интернет. Статус базы виден в панели. Подробнее — [описание реализации и проверок](docs/GEOIP_DATABASE.md).

**Откат:** первое включение GeoIP переводит состояние в формат v2, даже если затем выключить фильтры. Версия 0.1.5 этот формат не читает. Перед включением сохраните защищённую резервную копию данных; простой откат образа после этого не поддерживается.

### Диагностика подключения

«Недавняя связь» означает handshake за последние 150 секунд, а не гарантию текущего подключения. Скорости — средние за интервал, в бит/с: ↓ отправлено клиенту, ↑ получено от него. Счётчики сервера могут включать служебный трафик; отправка не подтверждает доставку. До второй выборки показывается «Измерение…», а при ошибке или тайм-ауте — «Данные недоступны», не устаревшие скорости. Фактический интервал замера виден в раскрывающемся блоке диагностики.

## Параметры установки и конфликты

Установщик:

1. проверит архитектуру и TUN, а недостающие Docker, Compose v2, iproute2 и nftables установит через системный менеджер пакетов;
2. включит IPv4/IPv6 forwarding через `/etc/sysctl.d/99-awg-easy-3.conf`;
3. скачает готовый `linux/amd64` образ из GitHub Container Registry;
4. создаст первый профиль Home;
5. один раз покажет пароль и `vpn://`;
6. запустит контейнер;
7. без дополнительного вопроса включит одну проверку стабильного обновления после каждой загрузки ОС, если используется systemd или OpenRC.

Без `--port` и `AWG_PORT` чистая установка выбирает один случайный свободный UDP-порт из **20000–60000**, исключая прежний стандартный `51820`. Проверяются сокеты ОС и опубликованные порты Docker. Выбранный порт выводится после установки и попадает в профили: именно его нужно разрешить в firewall VPS/провайдера. Обычное обновление сохраняет порт; чистая переустановка выбирает заново, если порт не задан явно. Это не гарантирует защиту от обнаружения VPN или блокировки IP.

Необязательные параметры позволяют избежать конфликтов с другой инфраструктурой:

```bash
sudo ./install.sh --host vpn.example.com --port 51820 --panel-port 51821 --lang en
```

Поддерживаемые языки панели: английский (`en`, по умолчанию), русский (`ru`), фарси (`fa`, RTL), испанский (`es`) и упрощённый китайский (`zh-cn`). `--port` задаёт публичный UDP-порт AWG, а `--panel-port` — внутренний TCP-порт панели, который по-прежнему не публикуется в интернет.

Если внутренний TCP-порт панели по умолчанию занят, интерактивный запуск предложит ближайший свободный и позволит ввести другой. Явно переданный занятый `--port` или `--panel-port` считается ошибкой и никогда не заменяется молча. Поддерживаются APT, DNF, YUM, Zypper, Pacman и APK. NixOS распознаётся отдельно: вместо автоматического редактирования `configuration.nix` установщик выводит готовый декларативный модуль и команду однопоточного `nixos-rebuild`, безопаснее работающую на малом объёме RAM. Установщик не удаляет конфликтующие контейнеры, интерфейсы, маршруты или таблицы nftables: небезопасно разрешимые конфликты обнаруживаются до изменения сетевых настроек VPS.

## Совместимость и полевые проверки

Профилям AWG 3.x нужен клиент с поддержкой AWG 3.x; обычный WireGuard и старые AWG-клиенты несовместимы. AWG-Easy 3 независим от проектов клиентских приложений.

- **Android, проверенная альтернатива:** [AmneziaWG, выпуск v3.1.20260814](https://github.com/amnezia-vpn/amneziawg-android/releases/tag/v3.1.20260814). В настройках отображаются приложение **3.1.20260813** и движок **3.1.20260814**. 09.09.2026 пользователь подтвердил на Honor 50 импорт нашего `.conf`, подключение и доступ к панели по IPv4 и IPv6. Используйте импорт файла, не `vpn://`; **2.0.1 несовместима**. Имя скачиваемого файла короткое, из ASCII-символов, например `Honor_50.conf`; имя клиента в панели и содержимое профиля не меняются. Для имён только из нелатинских символов используется `AWG-client.conf`.
- **Компьютер, кандидат на проверку:** [Throne 1.3.0-beta.2](https://github.com/throneproj/Throne/releases/tag/1.3.0-beta.2) реализует поля AWG 3.x, включая `RandomTrailers` и `DisableCookies`. Для пробы используйте импорт `.conf`. Это бета; **доступ к IPv6-панели и Home-сеть с AWG-Easy 3 ещё не проверены на практике**, поэтому отсутствие IPv6-проблем не обещается.
- **Для опытных пользователей:** [Mihomo 1.19.30](https://github.com/MetaCubeX/mihomo/releases/tag/v1.19.30) реализует AWG 3.0/3.1. Требуется соответствующий YAML с `amnezia-wg-option.version: 3`; не каждая графическая оболочка содержит это ядро. Импорт, IPv6-панель и Home-сеть у нас пока не проверены.

**AmneziaVPN 5.0.2.1 на Android:** в сравнительном тесте на Honor 50 IPv6-панель открывалась с тайм-аутом, тогда как тот же профиль работал в отдельном AmneziaWG. В [коде обработки маршрутов Android](https://github.com/amnezia-vpn/amnezia-client/blob/5.0.2.1/client/android/protocolApi/src/main/kotlin/ProtocolConfig.kt) `::/0` заменяется на `2000::/3`, не включающий внутренний ULA-адрес панели даже в режиме «Все сайты». Используйте IPv4-адрес панели или проверенную Android-альтернативу. Вывод не распространяется автоматически на все версии и платформы AmneziaVPN. Интернет, DNS, сервисы Home-клиентов и discovery проверяются отдельно: открытие панели не подтверждает их работу.

Предыдущие полевые проверки, до **0.1.3** включительно. Добавлены разрешения IPv4/IPv6 для каждого клиента и сворачиваемые «Настройки доступа». После прежних испытаний Ubuntu/systemd на реальном VPS также проверены установка, миграция и перезагрузки Alpine/OpenRC. Последние UI-правки проверены локально в браузерах после удаления VPS. См. [описание выпуска](docs/releases/v0.1.3.md) и [полевой отчёт Alpine](docs/VPS_TEST_2026-08-31.ru.md).

На отдельной VPS уже проверены AWG 3.1, Docker-развёртывание, импорт в AmneziaVPN Android, IPv4/IPv6, изоляция Home/Guest и отзыв удалённых профилей. Серверная ретрансляция Home discovery и подмена адреса в SSDP также проверены между двумя реальными peers; видимость сервисов в приложении зависит от того, отправляет и принимает ли клиент multicast через VPN-интерфейс.

## Важные ограничения

- Миграции из AWG-Easy 2.x намеренно нет.
- Backup/restore намеренно отсутствует.
- Обычные WireGuard-клиенты не поддерживают AWG 3.x.
- Выборочная маршрутизация по GeoIP отложена до отдельного архитектурного решения: текущая версия всегда использует full tunnel.
- mDNS/SSDP relay не открывает порты и не является UPnP IGD.
- Серверная ретрансляция mDNS/SSDP и подмена SSDP `LOCATION` проверены захватом трафика между двумя реальными Home-клиентами. Некоторые сочетания Android VPN-клиента и приложения могут выполнять discovery только через физическую сеть и поэтому не показывать сервисы из туннеля; серверный relay при этом продолжает работать корректно.

Архитектура и точные решения описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), продуктовая спецификация — в [docs/PRODUCT_SPEC.ru.md](docs/PRODUCT_SPEC.ru.md).
