# wg-dual-easy

[English](README.md) | [Русский](README.ru.md)

## Что такое wg-dual-easy

Небольшая Docker-панель для AmneziaWG и стандартного WireGuard: два самостоятельных VPN-сервиса и единая команда `vpnctl`. Независимый некоммерческий форк [AWG-Easy 3](https://github.com/alexsemenovru/awg-easy-3).

> Текущий выпуск: **0.2.0**. При обновлении сохраняются клиенты, ключи и пароли. См. [описание выпуска](docs/releases/v0.2.0.md).

## Кратко о возможностях

- Создавайте и выдавайте VPN-профили через браузер; каждая панель доступна только через свой VPN.
- Объединяйте Home-клиентов в частную сеть или выдавайте Guest-клиентам только интернет.
- Управляйте обоими сервисами одной командой, с backup, диагностикой и откатом.

## Установка и первый вход

Требования: Linux VPS с архитектурой amd64/x86_64, доступ root, Git, `/dev/net/tun` и свободные входящие UDP-порты. WSL, macOS и BSD не поддерживаются. При необходимости установщик подготовит Docker Engine, Docker Compose v2, iproute2, nftables и Python 3 через поддерживаемый менеджер пакетов.

```bash
git clone --branch v0.2.0 https://github.com/a-baader/wg-dual-easy.git
cd wg-dual-easy
sudo ./vpnctl install --host PUBLIC_IP_OR_DOMAIN --lang ru
```

Замените `PUBLIC_IP_OR_DOMAIN` адресом VPS. Готовые образы скачиваются автоматически; сборка на сервере не нужна. Разрешите выбранные UDP-порты в firewall VPS и провайдера: AWG использует свободный случайный порт, WG — `51824` по умолчанию. Публичный доступ к TCP-портам панелей не требуется.

Установщик показывает прогресс, два отдельных пароля панелей и первые Home-профили:

- **AmneziaWG:** импортируйте ссылку `vpn://` в совместимый AmneziaVPN либо `/etc/vpn-easy-dual/bootstrap/awg.conf` в клиент AWG 3.x. Подключитесь и откройте `http://10.8.0.1:51821`.
- **WireGuard:** импортируйте `/etc/vpn-easy-dual/bootstrap/wg.conf` в стандартное приложение WireGuard. Подключитесь и откройте `http://10.9.0.1:51825`.

Используйте пароль соответствующей панели. Если установщик вывел другие внутренние адреса, используйте их. Панель доступна Home-клиентам своего VPN; Guest-клиентам и другому VPN доступ закрыт.

Если профиль потерян, повторно экспортируйте того же клиента:

```bash
sudo vpnctl client export --component awg --name admin --format vpn-url
sudo vpnctl client export --component wg --name admin --format conf --output /root/wg-admin.conf
```

Пароли и bootstrap-ссылки показываются в терминале. Публичный отчёт установки сохраняется в `/root/wg-dual-easy-install-result.json` с правами `0600`, без паролей и содержимого профилей. Для JSON в stdout вместо файла отчёта укажите `--json`.

### Панель как приложение

Подключите Home VPN, откройте панель и выберите в браузере «Установить приложение», «Добавить на главный экран» или «Создать ярлык». Это не устанавливает и не запускает VPN. Автоматическое предложение установки обычно требует HTTPS; для внутреннего HTTP-адреса может быть доступен только ярлык. Офлайн-кеш профилей не добавляется.

## Обновление и управление

```bash
sudo vpnctl update
```

Команда проверяет последний стабильный релиз и обновляет его исходники и готовые образы, с предварительным snapshot и откатом при сбое. Клиенты, ключи, пароли и порты сохраняются. Если релиз уже установлен или стабильного релиза нет, изменений не будет. RC и понижение версии не выбираются. При замене контейнеров возможен краткий разрыв VPN.

`sudo vpnctl` открывает меню из любого каталога; `sudo vpnctl help` показывает справку. Обычный вывод команд — читаемый текст и публичный JSON-отчёт в `/root`; `--json` явно включает JSON в stdout. Прогресс и вопросы идут в stderr.

В systemd/OpenRC установка включает однократную проверку стабильных образов через пять минут после загрузки ОС; systemd добавляет случайную задержку до двух минут. Управление: `sudo vpnctl auto-update status|enable|disable|run`. Для обновления исходников host manager используйте `vpnctl update`.

`vpnctl uninstall all` удаляет сервисы и рабочие данные, сохраняя внутренние backup. `vpnctl purge` также удаляет внутренние backup и неиспользуемые образы с подтверждённым владением. `vpnctl reinstall` выполняет чистую установку с новыми ключами и паролями. Удаление и чистая переустановка требуют явного подтверждения, в автоматизации — `--yes`.

Удаляются только ресурсы приложения. Docker, чужие контейнеры и текущие значения forwarding сохраняются. Исходники и внешние отчёты/экспорты остаются. Установленный `vpnctl` удаляется вместе с последним сервисом; после этого установку или restore запускают через исходный `./vpnctl`.

## Технические возможности

- Раздельные контейнеры AWG/WG, ключи, клиенты, авторизация и панели только внутри VPN.
- Нативный экспорт `.conf` и QR; для AWG также доступны ссылка и QR `vpn://`.
- Изоляция Home/Guest, права IPv4/IPv6 для каждого клиента и ограниченный NAT IPv6 при его доступности.
- Текущие скорости передачи, диагностика handshake/endpoint и пакетная проверка отдельным клиентом.
- Согласованные backup/restore, контролируемая миграция, восстановление транзакций и откат.
