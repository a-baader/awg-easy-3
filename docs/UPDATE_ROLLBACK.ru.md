# Обновление, rollback и прерывание операций

Обновления Dual запускаются вручную. При миграции оригинального AWG boot
updater отключается; независимый updater для WG не создаётся. Образы и релизы
не публикуются автоматически этой рабочей веткой.

Обновление использует заранее проверенный локальный JSON manifest:

```json
{
  "version": "0.1.6",
  "images": {
    "awg": "vpn-easy-awg:dual-dev",
    "wg": "vpn-easy-wg:dual-dev"
  }
}
```

В примере локальные сборки; для опубликованных релизов следует указывать
проверенные ссылки с digest. Здесь нет готового опубликованного Dual-релиза.
Не используйте latest. Manager закрепляет разрешённый образ по immutable
image ID, проверяет backend, Linux/amd64, tools и совместимость состояния.

```sh
sudo vpnctl update all --manifest /root/release.json --dry-run
sudo vpnctl update all --manifest /root/release.json --yes
```

Последовательность: общая блокировка, проверки образов и состояния, запрет
новых записей выбранных панелей с завершением уже начатых, остановка на время
snapshot, проверка snapshot, последовательная замена AWG/WG и healthcheck.
При наличии отдельного тестового peer выполните пакетный diagnose из CLI.ru.md.
Handshake и локальный HTTP healthcheck не доказывают выход клиента в Internet.

В transaction.json сохраняются предыдущая и целевая конфигурации, выбранные
компоненты, snapshot, PID владельца блокировки и фаза операции. До commit
ошибка возвращает предыдущие образы вместе с состоянием snapshot. Это полный
rollback данных, а не только смена image. До появления snapshot возвращается
исходная конфигурация; для миграции запускается сохранённый исходный контейнер.
Перед любыми действиями recovery подтверждает mount, image, host networking
и Compose service label существующих контейнеров. Чужие совпадения имён
приводят к остановке восстановления с сохранением журнала.

После сохранённой фазы committed допускается только завершение новой
конфигурации: прежний snapshot больше не восстанавливается, поскольку панель
могла подтвердить новую запись. Recover запускает и остановленные контейнеры,
проверяет их health и снимает запрет записи. Состояние maintenance закрепляется
также в конфигурации Compose, чтобы пересоздание контейнера до commit не
разрешило новые записи раньше времени.

После SIGTERM выполняется обработка прерывания. После SIGKILL или reboot
оператор запускает `sudo vpnctl recover --yes`. Общая flock освобождается
ядром; legacy mkdir-lock автоматически снимается только при совпадении с
владельцем журнала и подтверждённом отсутствии процесса. Живая или неизвестная
блокировка не снимается. При повторном использовании PID потребуется ручная
проверка администратора; автоматического удаления такой блокировки нет.

Запись metadata, архивы, извлечённые файлы и замены каталогов используют fsync.
Это уменьшает риск потери подтверждённых данных при аварии, но не гарантирует
исправность накопителя и не заменяет внешний backup. Автоматическое выполнение
recovery после boot не настроено. В штатном состоянии Docker restart policy
unless-stopped запускает сервисы; намеренно остановленный сервис остаётся
остановленным. Полный reboot отдельной VM пока не проверен.

Регистрация CLI/sysctl/modules также сохраняет undo-запись в журнал до первой
записи системного файла. При незавершённой установке восстанавливаются прежние
байты и права своих файлов или удаляются только созданные файлы. Если после
регистрации файл изменён администратором, recovery сохраняет его и сообщает
о конфликте. Повторный запуск после ручного разрешения конфликта использует
тот же журнал; удалять журнал для обхода защиты не следует.
