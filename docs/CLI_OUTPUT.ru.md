# Вывод vpnctl и прогресс установки

По умолчанию команды с JSON-результатом показывают читаемый текст, подобно
справке: заголовки, названия полей и списки с отступами. JSON-скобки и кавычки
сериализации в обычном выводе не используются.

```sh
sudo vpnctl status
sudo vpnctl install --host vpn.example.org --lang ru
sudo vpnctl update
```

Для JSON в stdout нужна явная опция:

```sh
sudo vpnctl status --json
sudo vpnctl install --host vpn.example.org --lang ru --json
```

При `--json` stdout содержит один JSON-документ; прогресс, предупреждения и
интерактивные вопросы идут в stderr. Отдельный файл результата не записывается.
JSON установки по явному `--json` включает bootstrap-данные, как и раньше.

## Файлы результатов

Без `--json` публичный JSON-отчёт сохраняется с правами `0600`, доступен root.
После результата команда показывает путь к файлу:

- install и reinstall: `/root/wg-dual-easy-install-result.json`;
- status: `/root/wg-dual-easy-status-result.json`;
- update: `/root/wg-dual-easy-update-result.json`;
- client list: `/root/wg-dual-easy-client-list-result.json`;
- auto-update status: `/root/wg-dual-easy-auto-update-status-result.json`;
- остальные: `/root/wg-dual-easy-<команда>-result.json`, с действием для client
  и auto-update.

Отчёт содержит application/report_version, время, команду, success и публичный
result. Отчёт установки также содержит адреса панелей, UDP-порты и пути
к bootstrap-профилям. Пароли, приватные и preshared keys, session secrets,
содержимое конфигураций и ссылки vpn:// в отчёт не сохраняются.
Пароли и bootstrap-ссылки при обычной установке показываются только в терминале.

Файл предыдущего результата этой команды заменяется атомарно. Символьная ссылка,
чужой файл или объект другого типа не перезаписываются. Если сохранить отчёт
не удалось, команда сообщает об этом и возвращает ненулевой код; уже успешно
выполненная операция не откатывается из-за файла отчёта. Однократный пароль
выводится до записи файла, чтобы ошибка диска не скрыла его от оператора.

Файл сохраняется и для результата --dry-run; установка VPN и её конфигурация
при этом не меняются. Это внешний отчёт в /root: purge сохраняет такие файлы,
как сохраняет внешние экспортированные профили и backup.

help, показ нового пароля, поток logs --follow и вывод conf/QR/vpn:// команды
client export без --output имеют собственный текстовый формат. Сохранение
профиля через client export --output остаётся явным экспортом содержимого
профиля; публичный отчёт такой команды содержит только путь к файлу.

## Прогресс установки

Установка сообщает о подготовке зависимостей, проверке системы и портов,
подготовке/загрузке/проверке или сборке образов, подготовке конфигураций и
профилей, запуске AWG/WG и ожидании healthcheck, регистрации vpnctl и настройке
проверки обновлений после загрузки ОС. Переустановка и дополнение установки
также показывают выполняемые этапы.

Во время долгого этапа основной VPN-установки каждые 10 секунд выводится
его название и прошедшее время. Менеджер системных пакетов показывает
собственный прогресс. Процент не придумывается: показывается реальная выполняемая операция.
При откате и ошибке выводятся соответствующие сообщения; успешное завершение
показывается только после завершения установки. Прогресс не содержит паролей,
профилей или ответов RPC. Вывод подготовки системных зависимостей направляется
в stderr, поэтому он не смешивается с JSON.

Протокол проверок: [CLI_OUTPUT_TEST_REPORT.ru.md](CLI_OUTPUT_TEST_REPORT.ru.md).

## Цветной вывод

В терминале vpnctl автоматически выделяет заголовки и названия полей голубым,
успешные состояния — зелёным, предупреждения и вопросы подтверждения — жёлтым,
ошибки — красным. Цвета используются в справке, результатах команд, прогрессе
установки и ранних сообщениях launcher до установки Python. Подтверждение
опасных операций по-прежнему требуется явно.

stdout и stderr проверяются отдельно: при перенаправлении результата в файл
он остаётся обычным текстом, а прогресс в терминале может сохранять цвета.
В `--json`, JSON-файлах результатов и непосредственно экспортируемых профилях
`.conf`, QR-кодах и ссылках `vpn://` управляющие коды цветов не добавляются.
Поток журналов контейнеров передаётся как прежде, без дополнительной раскраски.

Для отключения цветов задайте переменную `NO_COLOR` (даже пустую) или `TERM=dumb`:

```sh
sudo env NO_COLOR=1 vpnctl status
sudo env NO_COLOR=1 vpnctl install --host vpn.example.org --lang ru
sudo env TERM=dumb vpnctl help
```

Наличие `NO_COLOR` проверяется в окружении самого vpnctl: при запуске через sudo
используйте `sudo env`, как в примерах. Дополнительные пакеты для цветов не нужны.

Проверки цветов: [CLI_COLOR_TEST_REPORT.ru.md](CLI_COLOR_TEST_REPORT.ru.md).
