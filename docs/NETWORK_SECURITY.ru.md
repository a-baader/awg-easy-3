# Сетевая безопасность wg-dual-easy

Режим Dual включается `VPN_DUAL_MODE=1` в обоих сервисах. Без него AWG
сохраняет legacy поведение для совместимости. Переключать отдельный контейнер
в legacy вне vpnctl при действующем Dual deployment не следует.

## Границы

Каждому экземпляру принадлежат собственные интерфейс, state, runtime,
`inet awg_easy_3` либо `inet wg_easy_3`, sets и четыре маркера DOCKER-USER.
Правила применяются атомарным batch; произвольные чужие таблицы и отдельные
команды в policy отвергаются. Firewall включается до интерфейса; при
неудачной остановке движка защитные правила не удаляются. Остановка одного
компонента не удаляет таблицу и маркеры второго.

Home допускается к своей панели, своему Home и Internet. Guest — только
Internet. Запрещены доступ к другой VPN и к сервисам host, публичным адресам
VPS через VPN, loopback, link-local, частным IPv4/IPv6 адресам и Docker-сетям.
Home-to-Home своего VPN проверяется до запрета частных адресов. DNS — внешние
резолверы, указанные в профиле. Серверный DNS resolver не добавляется.
Фильтры семейств IP и GeoIP применяются до established shortcuts: отзыв
действует на уже существующий трафик. NAT ограничен своей подсетью и WAN.
Незапрошенный WAN→peer трафик запрещён.

Панель слушает только собственный VPN IP. Firewall дополнительно запрещает
пакеты к VPN-адресам сервера с чужих интерфейсов. Серверный loopback остаётся
доступен локальному healthcheck; все административные API требуют сессию.
Публичный endpoint capabilities содержит только имя backend и флаги функций,
без адресов, ключей, паролей и сведений о клиентах.

## Совместимость firewall

Контейнеры сбрасывают стандартный набор capabilities и получают только
`NET_ADMIN`. Для каждого установлены ограничения: 256 PID, 2 CPU и 1 GiB памяти
без дополнительного swap. Проверка обновления GeoIP с двумя базами по 700 тысяч
строк уложилась примерно в 402 MiB maxRSS. Это измеренный сценарий, не гарантия
для произвольно больших баз и числа клиентов.

По решению пользователя web/API пока остаётся в одном процессе с управлением
сетью: root и `NET_ADMIN` сохраняют риск изменения host network при компрометации
этого процесса. Полное разделение с привилегированным helper отложено.
Привязка каждой панели к собственному VPN-адресу и запреты Guest, WAN,
другой VPN-подсети и обхода через DNAT остаются обязательными.

`accept` в одной nft base chain не отменяет `drop` в другой. Собственная
политика работает вместе с Docker/UFW. DOCKER-USER получает только помеченные
правила своего интерфейса. Чужие policy не сбрасываются. Если UFW или другой
host firewall запрещает INPUT, он также должен разрешать Home-вход на
VPN-интерфейсе к собственной панели и discovery. Глобальное открытие TCP
панелей в WAN не требуется. При неизвестном конфликте preflight/диагностика
должны завершаться сообщением, а не отключать firewall.

В Dual discovery слушает только собственный VPN-адрес; multicast mDNS/SSDP
попадает на этот listener через собственное правило DNAT.
Фильтрация source/Home и цели fan-out независима для
обоих экземпляров. Ретрансляции между VPN, Guest и WAN нет. Наличие fan-out
на сервере не гарантирует multicast-поддержку конкретного клиентского UI.

## Проверка

```bash
node scripts/test-dual-network.cjs vpn-easy-awg:dual-stage7 vpn-easy-wg:dual-stage7
python3 scripts/test-dual-preflight.py
```

Сетевой тест разделяет один disposable namespace между двумя серверными
контейнерами, моделируя host network. Peer-контейнеры и имитация Internet
отдельные. Forward policy DROP и DOCKER-USER создаются только внутри тестового
namespace. Тестовые адреса Internet — алиасы в одноразовой сети; реальные
публичные серверы не используются. Перезапуски проверяются с неизменёнными
профилями и без перезапуска клиентов, с ожиданием обычных handshake timers.
Фактические результаты и ещё не проверенные сценарии — в TEST_REPORT.md.

## Запрет обхода через DNAT

До разрешений собственной панели и Home-to-Home Dual проверяет ct status dnat
для пакетов, пришедших с собственного VPN-интерфейса, и отбрасывает их для
IPv4/IPv6. Иначе публичный порт VPS с DNAT к собственной панели мог бы пройти
проверку уже переписанного destination IP. Эта защита не изменяет чужие NAT
таблицы и не препятствует обычному исходящему masquerade/SNAT VPN→Internet.

Исключение разрешает только discovery от активного Home своего интерфейса
на собственный адрес: текущий UDP-порт и исходная conntrack-пара назначения
должны совпадать с `224.0.0.251:5353` либо `239.255.255.250:1900`.
Исключение возвращает обработку к обычным правилам INPUT; оно не отменяет
проверку активного адреса, изоляцию Guest и запрет остальных DNAT-потоков.

Тест создаёт настоящий host listener с положительным WAN-контролем и отдельные
DNAT-правила к работающей WG-панели. Home и Guest проверяются по публичным
IPv4/IPv6 и Docker-адресу. Docker-адрес в клиентском стенде принудительно
маршрутизируется в VPN; внешний UDP движка отделён fwmark, чтобы тест не
обходил туннель по непосредственно подключённой сети Docker.

## Ограничение попыток входа

HTTP login использует фактический `socket.remoteAddress`, без доверия к
`X-Forwarded-For`. IPv4 и его IPv4-mapped представление используют один бюджет.
Для каждого адреса разрешён burst из пяти попыток, затем восстанавливается
одна попытка каждые 12 секунд. Общий бюджет экземпляра — burst 20 с пополнением
по одной попытке каждые три секунды. Учитываются также успешные попытки входа.

Не более двух проверок выполняются одновременно; очередь ожидающих login
отсутствует. Превышение лимита возвращает `429` и `Retry-After`. Таблица адресов
ограничена 1024 записями; записи без обращений пять минут удаляются. Бюджеты
хранятся в памяти и создаются заново при перезапуске контейнера.

Проверка bcrypt выполняется в отдельном worker thread с ограничением памяти
и сроком пять секунд. Ошибка/timeout возвращает общий `503`, без перехода к
проверке в основном HTTP event loop. Worker останавливается до освобождения
слота. Неверный login не занимает очередь изменений StateStore.
Успешный login перед выдачей сессии коротко входит в очередь и повторно
проверяет `passwordHash` и `sessionSecret`: смена пароля/секрета во время bcrypt
запрещает выдачу сессии по старой ревизии auth.

Бюджеты общие для IPv4/IPv6 HTTP listeners одного экземпляра, независимые
между AWG и WG. Они дополняют доступ только Home своей VPN-подсети.
