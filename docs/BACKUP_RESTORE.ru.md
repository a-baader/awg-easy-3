# Резервное копирование и восстановление Dual

```sh
sudo vpnctl backup all --output /root/dual-backup.tar.gz --yes
sudo vpnctl restore --file /root/dual-backup.tar.gz --component wg --dry-run
sudo vpnctl restore --file /root/dual-backup.tar.gz --component wg --yes
```

Backup останавливает выбранные компоненты на время копирования и запускает
те, которые работали перед копированием. Другой VPN при backup одного
компонента не останавливается. Все изменяющие host-команды используют общую
блокировку. Активные сетевые сессии при остановке прерываются.

Архив содержит state.json, ключи, auth, клиентов, политики, GeoIP-файлы и
манифест с версиями/схемами, конфигурацией manager, размерами и SHA-256 каждого
файла. Пароли панели в открытом виде в рабочем состоянии отсутствуют; bcrypt
и session secret входят в архив. Каталоги bootstrap и operations.jsonl
manager в архив данных приложений не входят; профили можно повторно получить
командой client export. Для snapshot проверяется читаемость архива, состав,
хеши и схемы, затем файл синхронизируется на диск и атомарно переименовывается.

Архив имеет права 0600. Это незашифрованная копия приватных ключей: храните её
на защищённом носителе вне VPS. Встроенного шифрования пока нет. По необходимости
зашифруйте проверенным внешним инструментом и отдельно храните ключ расшифровки.
Не отправляйте содержимое архива в логи, Git, чаты или публичные хранилища.

Restore сначала проверяет все файлы, схемы (AWG v1/v2, WG v3), точные образы,
совместимость состояния с backend и конфликты ресурсов. Извлечение выполняется
во временные каталоги: абсолютные пути, '..', symlink/hardlink, специальные
объекты, дубли, лишние файлы и неверные checksum отвергаются. Ограничения:
10000 файлов, 512 MiB на файл, 2 GiB суммарно. Каталоги создаются с правами
0700, файлы — 0600; данные синхронизируются до фиксации транзакции.

Проверка выполняется потоком: количество файлов, размеры и время ограничиваются
до чтения всего архива; избыточные PAX/GNU metadata и sparse отвергаются.
Сжатый архив ограничен 2 GiB, state.json — 16 MiB, manifest — 4 MiB,
время проверки/извлечения — 120 секунд на проход.

По умолчанию код из backup не выбирается: restore использует установленный
образ выбранного VPN, а fresh restore — проверенный образ текущего своего
релиза. Состояние проверяется на совместимость с этим образом.
`--dry-run` проверяет архив и план без pull/run Docker-образов; проверка состояния
через код выбранного образа выполняется только при настоящем restore.

Для осознанного восстановления с точным старым/custom image укажите
`--trust-backup-images`. Это отдельное доверие исполняемому коду: образ получит
host network и NET_ADMIN. Разрешены неизменяемые image ID/digest; обычный `--yes`
сам по себе доверие произвольному образу не даёт.

Перед заменой существующих данных restore запрещает изменения через UI/CLI,
дожидается уже начатых записей и создаёт проверенный snapshot текущего состояния.
После замены проверяются контейнеры и healthcheck. До commit ошибка приводит
к возврату прежнего образа и соответствующего состояния; после commit recovery
завершает новую версию, сохраняя принятые после commit записи. Чтение панели
и VPN-трафик продолжаются до предусмотренной остановки выбранного сервиса.

Частичный restore меняет только выбранный компонент. Текущие host data paths
сохраняются; настройки сети/ключи/политики выбранного компонента берутся из
архива и проверяются на конфликт. Для fresh restore требуются свободные
системные пути и каталоги data/data-wg в текущем проекте. Точные image ID из
архива при `--trust-backup-images` должны быть доступны локально либо по digest;
плавающий latest запрещён. Сохраняйте образы отдельно, если нужна аварийная
переносимость копии на новый хост.

При прерывании выполните `sudo vpnctl status --json`, затем
`sudo vpnctl recover --yes`. Не удаляйте transaction.json, snapshot или каталоги
.before-restore/.failed/.rollback вручную до успешного восстановления. Они
могут содержать единственную пригодную копию данных.

Переименование рабочих данных в `.before-restore-*` или `.failed-*` теперь
предварительно записывается в transaction.json вместе с исходным путём,
device и inode. После успешного commit или rollback учтённые временные копии
удаляются. При отказе очистки журнал сохраняется: `vpnctl recover --yes`
повторяет очистку, не заменяя принятые после commit данные. Подменённый каталог
или symlink не удаляется; восстановление останавливается с ошибкой владения.

Проверенные внутренние backup сохраняются после restore, rollback и обычного
uninstall; команда `purge` удаляет и их. Каталоги, оставшиеся от старых версий
без записи в журнале, автоматически не присваиваются приложению и не удаляются
по маске имени. Для них требуется отдельная проверка принадлежности и
содержимого администратором. Автоматического удаления старых архивов нет.
