# Проверка прогресса удаления

Дата: 29 октября 2026 года.

`uninstall` и `purge` показывают цветные этапы в stderr и итоговый отчёт
в терминале. Вложенный uninstall внутри purge использует тот же reporter:
сообщение об успешном завершении выводится один раз. При ошибке reporter
останавливается, успешное завершение не выводится. В dry-run прогресс
выполняемого удаления не запускается.

Автоматические проверки:

- `test-vpnctl-removal-progress.py`: 3 теста, успешно. Проверены heartbeat,
  очистка reporter при ошибке, uninstall одного сервиса и purge в обычном режиме,
  с --json и --dry-run (6 сценариев). Проверены этапы, однократное завершение,
  терминальный отчёт и единственный JSON-документ в stdout.
- Регрессии: manager 23, install contract 28, purge 19, source update 17,
  install progress 5, output 13, color 10 — всего 115 тестов, успешно.
- Python-модули и новый тест проверены через py_compile; git diff --check пройден.

Логи сохраняются локально в `/app/srv_awg/dual-work/evidence/removal-progress/`.

Интеграция `test-vpnctl-purge-integration.py`: успешно на реальных контейнерах
с образами 0.2.0 в одноразовом network namespace. Проверены dry-run,
удаление обоих VPN, данных, внутренних backup, vpnctl и выделенного образа;
сохранены исходники, внешний backup, чужой контейнер, чужая таблица nftables,
используемый чужим контейнером образ и текущие значения forwarding.
Повторный purge возвращает отсутствие изменений. VPS не затрагивался.
Проверки перезагрузки ОС и полевых устройств остаются отложенными.
