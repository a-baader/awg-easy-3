# Проверка прогресса и форматов вывода vpnctl

> Протокол разработки перед публикацией 0.2.0. Текущий сводный статус: [TEST_REPORT.md](TEST_REPORT.v0.2.3.md).

Дата: 2026-10-28.

## Автоматические проверки

- Прогресс: 5 тестов успешно.
- Форматы вывода: 11 тестов успешно.
- Host manager: 23 теста успешно.
- Контракт установки: 28 тестов успешно.
- Purge: 19 тестов успешно.
- Обновление исходников: 16 тестов успешно.
- Node: 256 тестов успешно; после правки документации дополнительно проверены
  README и release assets: 21 тест успешно из того же набора.
- Синтаксис Python/Shell и `git diff --check`: успешно.

Проверены реальный фоновый heartbeat, остановка потока прогресса, отсутствие
ложного завершения при ошибке, отсутствие прогресса у dry-run, этапы установки,
текстовый формат без сериализации JSON, явный JSON без файла, отчёт с правами
0600, адресами панелей и путями к профилям без сохранения секретов, фильтрация
вложенных приватных полей, защита чужих файлов и symlink. Однократный пароль
показывается и при ошибке записи отчёта. Вопросы подтверждения не попадают
в stdout; сохранение существующей установки с --json возвращает один JSON.

## Настоящие контейнеры

`scripts/test-vpnctl-install-output-integration.py` успешно выполнен от root
в одноразовом Docker network namespace с временными системными каталогами:

- Обычная установка обоих VPN показывает этапы в stderr, читаемый результат
  и однократные пароли/ссылки в терминале.
- Публичный JSON-файл имеет права 0600, содержит оба адреса панелей и пути
  к профилям; реальные пароли и vpn:// в него не попадают.
- Оба сервиса достигли healthy.
- status --json возвращает один JSON в stdout без отдельного отчёта.
- Повторная чистая установка с --json возвращает один JSON с bootstrap,
  прогресс отдельно и не меняет прежний публичный отчёт.

stdout установки с реальными паролями не записывался в файлы проверки.
Реальный systemd/OpenRC и reboot не проверялись; изменения VPS не выполнялись.
Новые unit и интеграционные проверки добавлены в GitHub Actions.
