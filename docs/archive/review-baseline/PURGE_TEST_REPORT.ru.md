# Проверка vpnctl purge

> Протокол разработки перед публикацией 0.2.0. Текущий сводный статус: [TEST_REPORT.md](TEST_REPORT.v0.2.3.md).

Дата: 2026-10-28. Исходники и внешние backup сохраняются;
внутренние backup удаляются по явному выбору пользователя.

## Автоматические проверки

- `scripts/test-vpnctl-purge.py`: 19 тестов успешно.
- `scripts/test-vpnctl.py`: 23 теста успешно.
- `scripts/test-vpnctl-install-contract.py`: 28 тестов успешно.
- Регрессионные тесты Node: 256 тестов успешно при реализации purge.
- Синтаксис Python и Shell, `git diff --check`: успешно.

Проверены явное подтверждение, dry-run без изменений, удаление всех активных
компонентов и внутренних backup, сохранение исходников и внешнего backup,
повторный вызов, очистка после обычного uninstall, защита символьных ссылок,
чужих контейнеров, общих системных каталогов и каталогов с неподтверждённым
владением. Изменённые администратором системные файлы сохраняются.

Отказ до фиксации удаления восстанавливает оба компонента из snapshot.
Сбой очистки после фиксации требует recover; удалённые клиенты не возвращаются.
Recover работает и после уже выполненного удаления внутренних backup.
Успешный purge не создаёт заново журнал операций.

Удаление образов проверено с несколькими собственными тегами, локальными
ссылками по digest, чужими тегами и использованием чужим контейнером.
`--force`, глобальные prune и Compose down не используются.

## Настоящие контейнеры

`scripts/test-vpnctl-purge-integration.py` успешно выполнен от root в одноразовом
Docker network namespace с временными системными каталогами:

- Установлены оба настоящих VPN-сервиса; dry-run сохранил работающие контейнеры
  и конфигурацию.
- Полный purge удалил оба контейнера, интерфейсы и таблицы приложения,
  рабочие данные, bootstrap, внутренние backup и установленный vpnctl.
- Выделенный неиспользуемый образ приложения удалён.
- Образ, используемый чужим контейнером, сохранён с указанием причины.
- Чужой контейнер и таблица nftables, внешний backup и исходники сохранены;
  значения IPv4/IPv6 forwarding не изменились.
- Повторный purge завершился без изменений.

Реальный systemd/OpenRC и перезагрузка ОС в этой проверке не использовались.
Изменений действующего VPS не выполнялось. Оба новых теста добавлены в CI.
