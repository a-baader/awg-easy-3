# Проверка привязки discovery к своему VPN

Дата: 29 октября 2026 года.

В dual-режиме для каждого сервиса создаются только два discovery-сокета:
UDP 5353 и 1900 на собственном VPN IPv4-адресе. Wildcard multicast-сокеты
не создаются. Политика nftables доставляет multicast Home-клиентов на
собственный VPN-адрес по двум точным правилам (группа и соответствующий порт).
Правила ограничены собственным входным VPN-интерфейсом и набором home4.

Автоматические проверки: 258 Node-тестов успешно, включая новые проверки
адресов bind для AWG/WG и ограничений правил перенаправления. Проверка
npm run check и синтаксиса сетевого теста пройдена.

Тестовые образы собраны локально поверх опубликованных образов 0.2.0 с
заменой модулей src/lib на текущие. Release и опубликованные образы не менялись.
Все сетевые операции теста выполняются в одноразовых контейнерах и namespace.
Проверки не затрагивают реальную установку на VPS.

Полный `test-dual-network.cjs` с новыми тестовыми образами завершён успешно.
Проверены отсутствие wildcard-слушателей, наличие bind на адресах своего VPN,
реальная ретрансляция mDNS/SSDP между Home-клиентами и отсутствие пакетов
у Guest, другого VPN и WAN. Также пройдены IPv4/IPv6, доступ к панелям,
изоляция host/Docker, GeoIP fail-closed, отзыв активного TCP и независимые
остановка/запуск обоих серверов. Добавленные проверки bind выполняются в CI.

Вывод ss, журналы сборки и сетевого теста сохранены в
`/app/srv_awg/dual-work/evidence/listening-ports/`.
В этом namespace есть дополнительные тестовые HTTP-службы и DNS Docker;
они принадлежат стенду и не являются новыми слушателями приложения.
Проверки перезагрузки ОС и полевых устройств остаются отложенными.
