# VPN Easy Dual 0.2.0-rc.2

Предварительный выпуск с новым установщиком и управлением через `vpnctl`.
Два самостоятельных Linux/amd64 образа:

- `ghcr.io/a-baader/awg-easy-3-awg:0.2.0-rc.2` — AmneziaWG;
- `ghcr.io/a-baader/awg-easy-3-wg:0.2.0-rc.2` — стандартный userspace WireGuard.

## Изменения

- Корневой `install.sh` делегирует установку `vpnctl`. Поддерживаются исходные
  `--host`, `--port`, `--panel-port`, `--lang`, `--uninstall`, `--reinstall`,
  переменные `AWG_*`, проверка параметров до установки зависимостей и запуск
  из любого каталога. Endpoint определяется через `ip -4 route get 1.1.1.1`.
- Установка без явных образов получает проверенный manifest именно выбранной
  версии, проверяет SHA256SUMS и закрепляет образы по digest. `--build` и явные
  `--awg-image`/`--wg-image` остаются доступны.
- Чистая переустановка создаёт новые ключи, пароль и первого Home-клиента;
  полная переустановка сбрасывает настройки проекта. До изменения данных
  создаётся snapshot; ошибка до commit возвращает прежнее состояние.
- Удаление и чистая переустановка требуют подтверждения; для автоматизации
  используется `--yes`. Рабочие данные удаляются, внутренние backup остаются.
- При удалении последнего сервиса удаляется установленный `vpnctl`. Исходники
  остаются для новой установки и восстановления. Docker, чужие контейнеры,
  firewall и текущие значения forwarding сохраняются. Изменённые системные
  файлы не удаляются как собственные.
- В systemd/OpenRC по умолчанию включается однократная проверка stable-релиза
  после загрузки. Устаревшие компоненты обновляются с backup и rollback;
  версии AWG/WG учитываются отдельно, более новый backend не понижается.

Панели по-прежнему доступны только через Home соответствующего VPN.
Сохранены AWG `vpn://`, native `.conf` и QR; WG использует стандартный `.conf`/QR.
Инструкция: `docs/INSTALL_DUAL.ru.md`. Проверки: `docs/TEST_REPORT.md` и asset
`TEST_REPORT.ru.md`. Образы и manifest публикуются после успешного полного CI
для commit этого тега. `SHA256SUMS` включает manifest, команду и отчёт.

## Обновление с RC1 без удаления клиентов

Сначала получите исходники тега `v0.2.0-rc.2` в прежнем каталоге установки,
сохранив рабочие данные. Скачайте `release-manifest.json` этого выпуска и выполните:

```sh
sudo ./vpnctl update all --manifest /путь/к/release-manifest.json --yes
sudo ./vpnctl auto-update enable
```

Update создаёт snapshot, сохраняет клиентов и обновляет собственные установленные
команды из текущих исходников. Изменённые чужие файлы не перезаписываются.
Не используйте `reinstall` для сохранения клиентов: он создаёт чистую установку.

## Отложенные проверки

По решению пользователя reboot отдельной VM, reboot во время update/restore,
официальные приложения на физических Windows/Android/iOS устройствах и полевые
проверки выполняются позже. SIGKILL, restart контейнеров и проверки unit-файлов
не заменяют reboot. Выпуск остаётся prerelease и не получает `latest`.
