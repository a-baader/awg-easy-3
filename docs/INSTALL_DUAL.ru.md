# Установка VPN Easy Dual

Предварительный релиз v0.2.0-rc.2 включает новый установщик vpnctl.
Полный reboot и полевые устройства пока отложены.
Порядок первого входа и безопасного сосуществования из PRODUCT_SPEC.ru.md
распространяется на каждый из двух сервисов. Параметры работающего VPS не являются
основанием менять проектные defaults или ослаблять изоляцию.

Поддерживается native Linux/amd64 с root-доступом и /dev/net/tun. Сначала получите
проверенную ревизию этого форка. Путь запуска не влияет на установку:
рабочие данные по умолчанию размещаются рядом с исходниками. Установка с
закреплёнными опубликованными образами (сборка на сервере не требуется).
Установщик получает manifest именно версии из VERSION, проверяет SHA256SUMS
и сохраняет выбранные digest в конфигурации. До публикации assets этой версии
используйте `--build` или явные ссылки на образы:

```sh
sudo /путь/к/awg-easy-3/vpnctl install --host vpn.example.org --lang ru
```

Совместимый `sudo /путь/к/awg-easy-3/install.sh` передаёт все параметры в
`vpnctl install`. Для локальной сборки из каталога исходников:

```sh
sudo ./vpnctl install --build --host vpn.example.org --lang ru
```

Или предварительно выполните сборку из BUILD.md и укажите теги явно:

```sh
sudo ./vpnctl install --host vpn.example.org \
  --awg-image vpn-easy-awg:dual-dev --wg-image vpn-easy-wg:dual-dev
```

Установщик предлагает установить недостающие Docker Engine, Compose v2,
iproute2, nftables и Python 3 средствами поддерживаемого пакетного менеджера.
В терминале установка недостающих пакетов запрашивается; без терминала
пакеты устанавливаются автоматически, как в оригинале. `--yes` также снимает
интерактивный вопрос о пакетах, но для удаления данных он служит явным подтверждением. На NixOS выводится отдельный модуль,
строка imports и команда nixos-rebuild с max-jobs=1 и cores=1; configuration.nix
автоматически не изменяется. Все действия выполняются новым `vpnctl`.

До изменения VPN проверяются архитектура, Docker, Compose, TUN, интерфейсы,
имена контейнеров, таблицы nftables, занятые TCP/UDP-порты и пересечения IPv4/IPv6
маршрутов во всех таблицах. Занятый default-порт в терминале позволяет выбрать
другой; явно заданный занятый порт вызывает ошибку. Чужие объекты не удаляются и
не переименовываются. --dry-run выполняет проверки без установки зависимостей,
создания профилей, сборки и запуска контейнеров; зависимости уже должны быть доступны.

## Первый вход

Каждому сервису создаются отдельные ключи сервера, клиент admin группы Home,
случайный пароль и независимое состояние. Сохраняется bcrypt-хеш пароля;
открытый пароль остаётся в памяти установщика и показывается один раз.
Повторный `install` предлагает сохранить установку (по умолчанию), удалить её
или чисто переустановить. Без терминала повторный `install` завершается без
изменений с ошибкой: требуется явный `uninstall` или `reinstall`.
Частичная установка дополняется недостающим компонентом без пересоздания существующего.
Если вывод потерян, используйте reset-password, затем экспорт admin.

Приватные профили сохраняются с правами 0600 под
/etc/vpn-easy-dual/bootstrap: awg.conf, awg.vpn-url, wg.conf. Первая AWG-ссылка
vpn:// показывается один раз. WG импортируется стандартным приложением
WireGuard через .conf; vpn:// для него не создаётся. Профиль admin нужен для
подключения к панели; скопируйте его на своё устройство защищённым способом.

После подключения соответствующего Home-профиля откройте:

- AWG: http://10.8.0.1:51821/;
- WG: http://10.9.0.1:51825/.

Панели слушают только собственные внутренние адреса VPN. TCP ports в Docker
не публикуются. Guest, другой VPN и внешние подключения к панелям запрещены.
Home-клиентам запрещены остальные host services, включая публичные порты VPS.
Пароль меняется в панели или локально через vpnctl; смена отзывает все сессии.
Языки: en (default), ru, fa (RTL), es, zh-cn.

Новая AWG-установка выбирает свободный случайный UDP-порт 20000–60000, кроме
51820. WG default UDP 51824. Опции --awg-port, --wg-port, --awg-panel-port,
--wg-panel-port, --awg-subnet, --wg-subnet, --awg-interface, --wg-interface
задают ресурсы до установки. Существующий AWG-порт при миграции сохраняется.
Откройте выбранные UDP-порты во внешнем firewall провайдера. TCP-порты панелей
открывать во внешнем firewall не требуется.

## Миграция оригинальной версии

Поддерживается исходный AWG-Easy 3 0.1.6 со схемой v1/v2; версия приложения
проверяется по самому образу. Экспериментальные версии не мигрируются. Неизвестные установки
не преобразуются. Опознаются Docker Compose labels, host networking, mount
/data и состояние; для работающего AWG сверяются public key и listen port.
Перед заменой контейнера он останавливается и создаётся проверенный архив.
Boot auto-updater оригинала отключается и заменяется единым updater Dual.
По умолчанию проверка stable-релиза после загрузки ОС включена для systemd/OpenRC.
Подробности — в UPDATE_ROLLBACK.ru.md.

Миграция оригинального 0.1.6 проверена в одноразовом окружении: состояние и
профиль сохранились побайтово, ранее подключённый клиент продолжил передавать
HTTP без перезапуска и перевыпуска профиля. Это не проверка reboot VPS или
Windows-клиента. До закрытия TEST_REPORT
не применять рабочую ветку к единственному рабочему серверу.

## Параметры оригинального установщика

`--host`, `--port`, `--panel-port`, `--lang`, `--uninstall`, `--reinstall`,
`--help` поддерживаются через `vpnctl install` и `install.sh`.
`--port` и `--panel-port` задают порты AWG; для второго сервиса используются
`--wg-port` и `--wg-panel-port`. Поддерживаются переменные `AWG_HOST`, `AWG_PORT`,
`AWG_PANEL_PORT`, `AWG_LANG`, а также `WG_PORT` и `WG_PANEL_PORT`. Явные параметры
команды имеют приоритет. Порты и язык проверяются до установки зависимостей.
Без `--host` endpoint берётся из исходного адреса `ip -4 route get 1.1.1.1`,
как в оригинале; при NAT задайте внешний адрес явно через `--host`.

## Удаление и чистая переустановка

```sh
sudo vpnctl uninstall wg
sudo vpnctl reinstall all --host vpn.example.org --lang ru
# Явное подтверждение для автоматизации:
sudo vpnctl uninstall all --yes
```

Операция предупреждает об удалении рабочих клиентов, ключей, пароля, настроек
и bootstrap-профилей. Без терминала необходим `--yes`. Внутренние backup
сохраняются вместе со старыми ключами и клиентами; они пригодны для restore.
Переустановка сначала проверяет окружение и образы, создаёт snapshot, а затем
создаёт новые ключи, пароль и первого Home-клиента. Ошибка до commit возвращает
прежнее состояние. При полной переустановке язык и остальные настройки проекта
возвращаются к defaults, если их не задали заново. При частичной сохраняются
настройки оставшегося сервиса. Каталоги данных остаются по прежним путям.

Удаление одного компонента сохраняет второй и `vpnctl`. При удалении последнего
удаляются установленные команды `vpnctl` и `awg-easy-3`, указатель исходников и
принадлежащие проекту sysctl/modules/updater-файлы. Изменённые администратором
файлы и чужие symlink сохраняются. Исходники и внутренние backup остаются;
новую установку запускают через `/путь/к/исходникам/vpnctl install`.
Docker, образы, чужие контейнеры/сети/firewall не удаляются. Текущие значения
forwarding хоста не сбрасываются; глобальный `sysctl --system` не вызывается.
